Influmatics UX and Pipeline Improvement Plan

이 문서는 현재 preview 사이트를 더 사용하기 쉽게 만들기 위한 제품/프론트엔드/서버/분석 엔진 개선 계획입니다. 목표는 사용자가 필수 입력만 넣고, 배경 데이터셋, 날짜 메타데이터, TreeTime outlier 처리, FASTQ mapping을 앱이 최대한 자동으로 처리하게 만드는 것입니다.

기준 브랜치: codex/feature/frontend-ui · 작성일: 2026-06-28 · preview: https://influmatics-ca8ef--branch-codex-feature-frontend-ui-zk3l5hza.web.app/

서비스 범위는 공개 과거 influenza A/H3N2 HA 서열의 후향 분석과 교육용 시각화입니다. 새 변이 설계, 감염성/전파력/병원성/면역회피/항바이러스제 내성 향상 추천, wet-lab protocol, synthesis, reverse genetics, virus rescue 기능은 넣지 않습니다.

1. 제품 방향 한 줄 요약

현재 앱은 사용자가 target FASTA, background FASTA, tree date metadata CSV, tree outlier file을 직접 맞춰서 넣어야 합니다. 앞으로는 Target 파일 + 검체 수집일 + 분석 preset 선택만으로 기본 분석이 돌아가게 바꿉니다.

1. Target FASTA 또는 FASTQ 업로드
2. Date 검체 수집일 입력
3. Dataset H3N2 HA background preset 선택
4. QC Review target outlier 후보만 확인
5. Report tree, clade, antigenic, mapping 결과 다운로드

2. 왜 지금 UX가 불편한가

현재 입력 사용자 불편 개선 방향
Background FASTA 사용자가 GISAID/NCBI 등에서 직접 서열을 모으고 파일을 맞춰야 합니다. 앱이 curated background dataset을 제공하고, 사용자는 dataset preset만 선택합니다.
Tree date metadata CSV 시퀀스 이름에서 날짜를 뽑아 CSV 양식으로 맞추는 작업이 반복됩니다. background 날짜는 dataset manifest에서 자동 생성하고, target 날짜만 입력받습니다.
Tree outlier file 사용자가 outlier 목록 파일을 직접 준비하기 어렵습니다. background outlier는 dataset 관리자가 미리 큐레이션하고, target outlier는 QC Review 탭에서 선택합니다.
FASTA-only target 원시 FASTQ만 가진 사용자는 별도 mapping/consensus 과정을 먼저 해야 합니다. FASTQ 업로드를 받아 reference-based mapping, coverage, consensus FASTA를 먼저 만들고 이어서 분석합니다.

3. Background Database 전략

Nextclade처럼 분석에 필요한 파일을 묶은 dataset bundle 개념을 도입합니다. Nextclade 공식 문서도 dataset을 reference, pathogen config, optional annotation/tree 등으로 구성하고, 버전 관리를 통해 재현성을 확보하는 방식을 사용합니다.

사용자에게 보이는 형태

  • Background preset: Global H3N2 HA representative set
  • Season range: Recent 3 seasons, 2010-present, custom
  • Sampling density: fast, balanced, full
  • Region focus: global, Korea/East Asia, custom metadata filter

서버 내부 파일

  • background.fasta: representative HA sequences
  • metadata.csv: name, collection_date, region, source, accession
  • tree_dates.csv: TreeTime용 자동 생성 날짜 파일
  • background_outliers.txt: 관리자가 미리 제외한 outlier
  • manifest.json: dataset id, version, provenance, license

권장 디렉터리 구조

data/background_sets/
  h3n2_ha_global_representative/
    2026-06-28/
      manifest.json
      background.fasta
      metadata.csv

Manifest 예시

{
  "id": "h3n2_ha_global_representative",
  "label": "H3N2 HA global representative background",
  "version": "2026-06-28",
  "subtype": "H3N2",
  "segment": "HA",
  "date_range": ["2010-01-01", "2026-06-01"],
  "sequence_count": 1200,

  "excluded_background_ids_file": "background_outliers.txt",
  "tree_dates_file": "tree_dates.csv"
}
GISAID-derived raw FASTA/metadata는 공개 repo나 public Firebase/GCS에 넣으면 안 됩니다. GISAID 데이터를 쓰려면 접근권, 재배포 제한, 공동 사용자 범위를 먼저 확인하고, 공개 앱 내장 DB에는 재배포 가능한 공개 데이터만 넣는 것을 기본 원칙으로 둡니다.

4. Tree Date Metadata 자동화

목표는 사용자가 CSV를 직접 만들지 않게 하는 것입니다. background 날짜는 dataset manifest에서 자동으로 가져오고, target 날짜는 upload form의 Target collection date 하나만 입력받습니다.

대상 날짜 생성 방식 검증
Background metadata.csv의 collection_date에서 tree_dates.csv 자동 생성 날짜 형식, 중복 name, 미래 날짜, 너무 낮은 precision 검사
Target FASTA 사용자가 입력한 검체 수집일을 target sequence name에 매핑 필수 입력으로 두고 YYYY, YYYY-MM, YYYY-MM-DD 허용
Target FASTQ FASTQ 파일명 또는 사용자가 입력한 sample id에 collection date 연결 consensus FASTA 생성 후 동일한 target id로 날짜 매핑

날짜가 FASTA header에 들어있는 경우도 자동 파싱 후보로 삼되, 사용자가 직접 입력한 날짜를 우선합니다. 분석 결과에는 최종 사용된 날짜 파일을 generated_tree_dates.csv로 남깁니다.

5. Outlier 처리 UX

지금처럼 사용자가 outlier 파일을 올리는 방식은 개발자용에 가깝습니다. 일반 사용자는 target이 시간축/트리에서 이상하게 배치되는지만 확인하면 됩니다.

Run 1 IQ-TREE + TreeTime QC
Auto exclude curated background outliers 제거
Candidate list target outlier 후보 표시
User confirm checkbox로 target 제외/유지
Final run 확정 목록으로 최종 tree 생성

새 탭 제안: QC Review

  • TreeTime residual, clock filter 여부, collection date, sequence id를 표로 보여줍니다.
  • background outlier는 자동 제외되며 사용자가 직접 편집하지 않게 합니다.
  • target outlier 후보만 사용자에게 선택권을 줍니다.
  • 기본 버튼은 Use recommended QC입니다. 고급 사용자는 Manual review를 엽니다.

6. FASTQ 입력과 Reference-based Mapping

FASTQ 입력을 지원하면 사용자는 원시 read 파일만 넣고도 consensus FASTA와 분석 결과를 받을 수 있습니다. repo에는 이미 influmatics/consensus.py wrapper와 legacy/original_scripts/auto_pipeline.sh가 있어 재사용 후보가 있습니다.

이 기능은 dry-lab read processing입니다. wet-lab protocol, 배양, 합성, reverse genetics, virus rescue와 관련된 안내는 제공하지 않습니다.
입력 모드 사용자 입력 서버 처리 결과물
FASTA mode Target HA FASTA, collection date 현재 legacy analysis로 바로 전달 기존 report, tree, clade, antigenic 결과
FASTQ mode FASTQ 또는 FASTQ.gz, collection date, sample id reference mapping, coverage QC, consensus FASTA 생성 후 분석 consensus FASTA, mapping QC, coverage plot/table, 기존 report
Batch FASTQ mode 여러 FASTQ 또는 zip 샘플별 consensus 생성 후 batch analysis 샘플별 QC와 통합 report

서버 출력 파일 제안

  • mapping/consensus.fasta
  • mapping/coverage.tsv
  • mapping/coverage.png
  • mapping/mapping_summary.json
  • mapping/run.log

Upload 화면 재구성

현재 UI 변경 후 UI

새 화면 구성

  • Upload: input type segmented control, target file, collection date, dataset preset
  • QC Review: TreeTime/coverage/date QC 후보 검토
  • Mapping: FASTQ mode일 때 consensus와 coverage 결과 표시
  • Tree: 기존 PNG뿐 아니라 추후 interactive tree viewer로 확장
  • Files: generated metadata와 dataset manifest도 다운로드 가능하게 표시

8. 서버/API 변경 계획

Endpoint 역할

9. 분석 엔진 변경 계획

  1. Dataset resolver: dataset id를 받아 background FASTA, metadata, outlier list 경로를 반환합니다.
  2. Date builder: dataset metadata와 target date로 tree_dates.csv를 자동 생성합니다.
  3. Outlier manager: curated background outlier와 TreeTime target outlier 후보를 분리합니다.
  4. FASTQ preprocessor: FASTQ를 consensus FASTA로 변환하고 mapping QC 결과를 저장합니다.
  5. Legacy CLI adapter: 최종적으로 legacy script에는 생성된 FASTA/metadata/outlier 파일만 넘깁니다.
  6. Manifest 확장: 사용한 dataset id/version, generated files, QC decisions, mapping summary를 기록합니다.

10. 구현 우선순위

Phase 목표 작업 난이도
P1 Background upload 제거 dataset registry, dataset selector UI, server resolver, generated tree_dates.csv 중간
P2 Tree metadata 자동화 target collection date validation, background metadata parser, generated metadata output 낮음-중간
P3 Outlier review UX QC Review tab, target-only decision, final rerun endpoint 중간-높음
P4 FASTQ mode FASTQ upload, consensus wrapper, mapping result files, Cloud Run dependency strategy 높음
P5 Interactive tree tree JSON/Newick serving, hover tooltip, target/vaccine/background layers 중간
추천 시작점은 P1입니다. Background dataset과 date 자동화를 먼저 만들면 사용자 입력 파일 수가 바로 줄고, 이후 QC Review와 FASTQ mode도 같은 dataset 구조 위에 얹기 쉬워집니다.

11. 데이터 큐레이션 기준

  • 공개 앱에 내장할 데이터는 재배포 가능성이 확인된 source만 사용합니다.
  • GISAID-derived raw sequence는 public repo, public bucket, Firebase asset에 포함하지 않습니다.
  • 각 dataset은 source, download date, filters, exclusions, sequence count, date range를 manifest에 남깁니다.
  • 대표 샘플링은 clade/subclade, year, region 균형을 기준으로 하되, 특정 변이의 우월성을 추천하지 않습니다.
  • background outlier list는 개발자가 관리하고, 사용자는 target outlier 후보만 확인합니다.

12. 추가 개선 제안

  • Analysis presets: Fast demo, Balanced, Full phylogeny 세 가지 preset으로 복잡한 옵션을 숨깁니다.
  • Run estimate: dataset 크기와 tree method에 따라 예상 소요 시간을 보여줍니다.
  • Dataset badge: 결과 report 상단에 사용한 dataset version을 크게 표시합니다.
  • Input validation: 날짜 누락, FASTQ/FASTA 혼동, 너무 큰 파일, subtype mismatch를 시작 전에 막습니다.
  • Result provenance: 모든 figure에 dataset id/version과 target date를 작게 표시합니다.
  • Advanced override: 연구자용으로 background/date/outlier 파일 직접 업로드 기능은 접힌 영역에 남깁니다.

13. 참고 자료

  • Nextclade dataset documentation : dataset 구성, versioning, custom dataset 개념 참고.
  • NCBI Virus : 공개 viral sequence 검색/다운로드 후보 source.
  • BV-BRC : Influenza A virus, surveillance, sequence tool, read utilities 등 참고.
  • GISAID Terms of Use : GISAID 데이터는 접근/재배포 조건을 확인해야 하며 public repo 내장 데이터로 취급하지 않습니다.
