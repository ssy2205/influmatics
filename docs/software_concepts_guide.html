Influmatics 프로젝트를 위한 소프트웨어 개념 지도

이 문서는 Influmatics를 웹페이지/서버/분석 파이프라인으로 발전시키기 위해 알아야 할 소프트웨어 개념을 한 번에 연결해서 설명합니다. 목표 독자는 의과학 연구동아리 팀원, 프론트엔드/백엔드를 맡을 친구, 그리고 그 친구가 사용할 Codex입니다.

기준 branch: JM · 핵심 분석 파일: legacy/h3n2_ha_analysis.py · 핵심 인수인계 문서: docs/web_handoff.html

이 프로젝트는 공개 과거 influenza A/H3N2 HA 서열의 후향 분석과 교육용 시각화에 한정합니다. 새 변이를 설계하거나 감염성, 전파력, 병원성, 면역회피, 항바이러스제 내성을 높이는 변이를 추천/생성/순위화하는 기능은 만들지 않습니다.

1. 전체 그림: 이 프로젝트는 무엇을 소프트웨어로 만드는가

Influmatics는 단순한 웹페이지가 아니라, 사용자가 서열 파일을 업로드하면 서버가 bioinformatics 분석 파이프라인을 실행하고, 결과를 대시보드로 보여주는 시스템입니다. 그래서 HTML/CSS/React만 알아서는 부족하고, Python CLI, 파일 입출력, 외부 프로그램 실행, 비동기 작업, 결과 파일 관리, 테스트, 배포 개념이 함께 필요합니다.

사용자 브라우저 └─ FASTA / metadata / Nextclade 결과 업로드 ↓ 웹 프론트엔드 └─ 입력 화면, 진행 상태, 결과 대시보드 ↓ HTTP API 백엔드 서버 └─ 파일 저장, run_id 생성, job 실행/상태 관리 ↓ subprocess Python 분석 엔진 └─ legacy/h3n2_ha_analysis.py ↓ 외부 도구 IQ-TREE / TreeTime / Nextclade 결과 파일 ↓ 결과 폴더 └─ run_manifest.json, phylogenetic_tree.png, CSV, HTML, Newick

가장 중요한 사고방식

  • 브라우저는 계산을 하지 않고, 입력과 결과 표시를 담당합니다.
  • 서버는 분석 작업을 시작하고, 상태를 추적하고, 결과 파일을 제공합니다.
  • 무거운 계산은 Python 분석 코드와 IQ-TREE/TreeTime 같은 외부 도구가 담당합니다.
  • 각 분석 실행은 독립적인 run_id와 결과 폴더를 가져야 합니다.
  • 웹 UI는 run_manifest.json을 읽어서 어떤 결과가 있는지 판단합니다.

MVP의 기준

처음부터 완벽한 cloud platform을 만들 필요는 없습니다. 가장 현실적인 MVP는 FastAPI 백엔드 + React/Vite 프론트엔드 + 로컬 runs 폴더 + subprocess 실행입니다. 분석 엔진은 현재의 legacy CLI를 그대로 사용하고, 웹은 그 주변을 감싸는 형태로 시작합니다.

3. 개발 환경과 의존성

같은 코드를 받아도 사람마다 Python 버전, 설치된 패키지, PATH 설정이 다르면 결과가 달라질 수 있습니다. 그래서 개발 환경을 명시적으로 관리해야 합니다.

권장 로컬 경로

Windows에서는 OneDrive, 한글, 공백이 포함된 경로도 작동할 수 있지만, 외부 CLI 도구와 서버 실행을 고려하면 짧고 단순한 경로가 안정적입니다. 

C:\dev\influmatics

가상환경

가상환경은 프로젝트별 Python 패키지 설치 공간입니다. 전역 Python에 모든 패키지를 설치하면 프로젝트 간 충돌이 생기므로, 웹 개발자는 반드시 가상환경을 쓰는 편이 좋습니다. 

cd C:\dev\influmatics
py -3.11 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,bio,web]"
python -m pip install numpy matplotlib biopython treetime

의존성 종류

종류 예시 관리 방법

외부 실행 파일 iqtree2.exe, nextclade PATH 등록 또는 서버 설정 파일에서 경로 지정

5. 파일, 데이터, manifest

이 프로젝트는 데이터베이스보다 파일 기반 workflow가 먼저입니다. 사용자가 업로드한 파일, 분석 중간 파일, 최종 결과 파일을 run별로 정리해야 합니다.

run directory 개념

분석 한 번을 하나의 run으로 보고, 고유한 run_id를 부여합니다. 이렇게 하면 여러 사용자가 동시에 분석해도 결과가 섞이지 않습니다. 

runs/
  20260624-101530-a8f3/
    inputs/
      target.fasta
      reference.fasta
      background.fasta
      vaccine.fasta
      tree_dates.csv
      nextclade_results.tsv
    results/
      run_manifest.json
      phylogenetic_tree.png
      phylogenetic_tree.newick
      antigenic_site_mutations.csv
      antigenic_distance_to_vaccine.csv
      clade_assignments.csv
    run.log
    status.json

manifest란 무엇인가

run_manifest.json은 분석 결과를 설명하는 목차 파일입니다. 프론트엔드는 결과 폴더를 직접 뒤지기보다 manifest를 읽고 화면을 구성해야 합니다. 

{
  "inputs": {
    "target": "...",
    "reference": "...",
    "background": "..."
  },
  "parameters": {
    "tree_method": "iqtree-treetime",
    "tree_plot_style": "figtree"
  },
  "counts": {
    "targets": 1,
    "background": 1148,
    "tree_display_tips": 836,
    "treetime_outliers_detected_final": 0
  },
  "outputs": {
    "phylogenetic_tree": ".../phylogenetic_tree.png",
    "clade_assignments": ".../clade_assignments.csv"
  }
}

파일 경로를 다룰 때 주의할 점

  • Windows 경로에는 공백과 한글이 들어갈 수 있으므로 항상 따옴표와 Path 객체를 사용합니다.
  • 사용자가 업로드한 원래 파일명을 그대로 신뢰하지 않습니다.
  • 서버 내부에서는 표준 이름으로 복사합니다. 예: target.fasta, background.fasta
  • 결과 파일은 run 폴더 밖으로 쓰지 못하게 제한합니다.
  • 대용량 background 파일은 매번 복사하지 않고 reference dataset으로 관리하는 방식을 나중에 고려합니다.

6. 외부 CLI 도구: IQ-TREE, TreeTime, Nextclade

IQ-TREE와 TreeTime은 Python 라이브러리처럼 import해서 쓰는 것이 아니라, 보통 별도 명령어로 실행하는 외부 도구입니다. 웹서버는 이 도구들을 직접 브라우저에서 돌리지 않고, 서버에서 실행해야 합니다.

subprocess 개념

subprocess는 Python 코드에서 다른 프로그램을 실행하는 방법입니다. 서버가 분석 스크립트를 실행하고, 분석 스크립트가 IQ-TREE/TreeTime을 실행하는 구조가 됩니다. 

import subprocess
import sys

cmd = [
    sys.executable,
    "legacy/h3n2_ha_analysis.py",
    "--target", "runs/run001/inputs/target.fasta",
    "--reference", "runs/run001/inputs/reference.fasta",
    "--background", "runs/run001/inputs/background.fasta",
    "--vaccine", "runs/run001/inputs/vaccine.fasta",
    "--outdir", "runs/run001/results",
    "--tree-method", "iqtree-treetime",
    "--tree-date-metadata", "runs/run001/inputs/tree_dates.csv",
    "--treetime-remove-outliers",
]

process = subprocess.Popen(
    cmd,
    stdout=subprocess.PIPE,
    stderr=subprocess.STDOUT,
    text=True,
)

IQ-TREE

IQ-TREE는 maximum likelihood tree를 만드는 도구입니다. 계산량이 크고 시간이 걸릴 수 있으므로 웹 요청 하나 안에서 동기적으로 기다리면 안 됩니다.

  • 서버에 iqtree2 또는 iqtree2.exe가 설치되어 있어야 합니다.
  • PATH에 등록하거나, 분석 옵션으로 실행 파일 경로를 넘겨야 합니다.
  • 개발/미리보기에서는 --iqtree-fast를 사용할 수 있습니다.

TreeTime

TreeTime은 tree와 tip date를 이용해 time-scaled tree를 추정합니다. 날짜 metadata 품질이 중요합니다.

  • name,date 형태의 CSV/TSV를 준비합니다.
  • FASTA header 이름과 metadata name이 매칭되어야 합니다.
  • temporal outlier는 반복적으로 제거하고 다시 실행할 수 있습니다.

Nextclade

Nextclade는 clade assignment와 mutation annotation에 유용합니다. MVP에서는 Nextclade 실행까지 서버가 자동화하기보다, 먼저 Nextclade 결과 TSV 업로드를 지원하는 편이 구현이 단순합니다.

외부 CLI는 서버 환경에서 “설치되어 있는지”, “PATH에서 찾을 수 있는지”, “권한이 있는지”가 자주 문제됩니다. 서버 시작 시 health check로 iqtree2 -version, treetime --help를 확인하세요.

7. 백엔드 서버 개념

백엔드는 브라우저의 요청을 받아 파일을 저장하고, 분석 작업을 시작하고, 결과를 돌려주는 프로그램입니다. 이 프로젝트에서는 Python 기반 FastAPI가 적합합니다.

HTTP와 API

브라우저와 서버는 HTTP로 대화합니다. API는 서버가 제공하는 약속된 주소와 요청/응답 형식입니다.

Endpoint 역할 프론트엔드가 받는 것
POST /analyses 파일 업로드와 분석 시작 run_id, 초기 상태
GET /analyses/{run_id}/status 진행 상태 조회 queued/running/completed/failed, 로그 tail
GET /analyses/{run_id}/results manifest 기반 결과 조회 counts, outputs, warnings
GET /analyses/{run_id}/files/{filename} PNG/CSV/HTML/Newick 제공 파일 다운로드 또는 미리보기
POST /analyses/{run_id}/cancel 긴 분석 중단 cancelled 상태

백엔드가 담당해야 할 일

  • 업로드 파일을 검사하고 run 폴더에 저장합니다.
  • 분석 명령어를 안전하게 구성합니다.
  • 분석 작업을 background process로 실행합니다.
  • 로그를 run.log에 저장합니다.
  • 상태를 status.json 또는 데이터베이스에 저장합니다.
  • 완료 후 run_manifest.json을 파싱합니다.
  • 프론트엔드가 파일을 조회할 수 있게 제공합니다.

서버 코드 구조 예시

web/server/
  app.py              # FastAPI app과 endpoint
  analysis_runner.py  # subprocess 실행, 로그, 상태 관리
  schemas.py          # 요청/응답 데이터 모델
  settings.py         # 경로, IQ-TREE 위치, 용량 제한
  storage.py          # run 폴더와 파일 제공

프론트엔드는 사용자가 보는 화면입니다. 이 프로젝트의 프론트엔드는 예쁜 landing page보다 업로드, 실행 상태, 결과 확인이 핵심입니다.

Vite는 React 개발 서버와 build 도구입니다. 빠르게 시작할 수 있고, FastAPI와 분리해서 개발하기 좋습니다.

화면 구성

  1. Upload: target/reference/background/vaccine/date metadata/Nextclade result 업로드
  2. Options: TreeTime, outlier 제거, target date, IQ-TREE fast mode
  3. Run Status: 현재 단계, 로그 tail, cancel 버튼

  5. Tree: phylogenetic_tree.png 확대/다운로드
  6. Clade: clade_assignments.csv table/chart
  7. Antigenic: vaccine similarity, antigenic site mutations, cartography
  8. QC/Outliers: metadata conflict, TreeTime outliers
  9. Files: 전체 결과 파일 다운로드

프론트엔드 state

state는 화면이 기억해야 하는 값입니다. 예를 들어 선택한 파일, 실행 중인 run_id, 현재 status, manifest 결과 등이 state입니다. 

type RunStatus = "idle" | "queued" | "running" | "completed" | "failed" | "cancelled";

type AnalysisState = {
  runId: string | null;
  status: RunStatus;
  logTail: string[];
  manifest: RunManifest | null;
};

polling

분석은 오래 걸리므로 프론트엔드가 2-5초마다 /status를 호출해 진행 상황을 확인합니다. 이것을 polling이라고 합니다. 

setInterval(async () => {
  const status = await api.getStatus(runId);
  setStatus(status);
}, 3000);

9. 긴 작업과 job queue

IQ-TREE/TreeTime은 수 초에서 수십 분까지 걸릴 수 있습니다. 따라서 서버는 분석을 HTTP 요청 안에서 끝까지 기다리면 안 됩니다.

동기 처리와 비동기 처리

방식 설명 이 프로젝트에서의 적합성
동기 처리 요청이 들어오면 결과가 끝날 때까지 기다림 짧은 QC에는 가능하지만 full tree에는 부적합
비동기/background job 요청은 run_id만 반환하고 계산은 뒤에서 진행 권장 MVP 방식
queue/worker 작업을 queue에 넣고 별도 worker가 순서대로 실행 동시 사용자 증가 시 권장

MVP job 상태

{
  "run_id": "20260624-101530-a8f3",
  "status": "running",
  "started_at": "2026-06-24T10:15:30+09:00",
  "stage": "treetime",
  "progress_message": "TreeTime 실행 중",
  "return_code": null
}

나중에 필요한 운영 기능

  • 동시에 실행할 수 있는 job 수 제한
  • 오래 걸리는 job timeout
  • cancel 요청 시 child process까지 종료
  • 실패한 job의 로그 보존
  • 오래된 run 폴더 자동 삭제
  • 대용량 파일 업로드 용량 제한

10. 보안, 데이터 정책, 생물안전 범위

연구용 웹서비스라도 파일 업로드와 외부 프로그램 실행이 들어가면 보안 개념이 중요합니다.

파일 업로드 보안

  • 업로드 파일 확장자만 믿지 말고 실제 내용도 검사합니다.
  • 파일명을 그대로 저장하지 말고 서버 표준 이름으로 바꿉니다.
  • 상대경로 ../가 포함된 파일명은 무시합니다.
  • 파일 크기 제한을 둡니다.
  • 결과 파일 제공 시 run 폴더 밖 파일을 읽지 못하게 합니다.

subprocess 보안

사용자 입력을 문자열 하나로 합쳐 shell에 넘기면 위험합니다. 반드시 리스트 형태로 command를 만들고 shell=False 방식을 사용합니다. 

# 권장
subprocess.Popen([
    sys.executable,
    "legacy/h3n2_ha_analysis.py",
    "--target", str(target_path),
])

# 피해야 함
subprocess.Popen(f"python script.py --target {user_input}", shell=True)

데이터 정책

공개 데이터라도 재배포 조건이 다를 수 있습니다. 특히 제한된 원본 sequence dataset은 GitHub에 올리지 않고 로컬 또는 기관 내부 저장소로 관리해야 합니다.

생물안전 범위

웹 UI와 API 문구에서 “미래 유행 변이를 추천”, “백신주 제안”, “fitness 향상 변이 탐색”처럼 오해될 수 있는 표현을 피하세요. 현재 시스템은 과거 관찰 데이터의 후향 분석, annotation, visualization 도구입니다.
  • 허용: 공개 과거 H3N2 HA 서열의 clade, tree, antigenic site annotation
  • 허용: 이미 문헌에 보고된 marker의 후향 annotation
  • 허용: metadata 기반 region/time visualization
  • 금지: 새 변이 설계/생성/추천/순위화
  • 금지: 감염성/전파력/병원성/면역회피/내성 향상 목적의 기능
  • 금지: 실험 프로토콜, 합성, 배양, reverse genetics, virus rescue 안내

11. 테스트와 품질 관리

테스트는 “코드가 아직도 맞게 작동하는지” 확인하는 자동 점검입니다. 특히 연구 소프트웨어는 조용히 틀린 결과를 내는 것이 가장 위험하므로 테스트가 중요합니다.

현재 테스트

현재 repository에는 tests/ 아래 pytest 테스트가 있습니다. 최근 기준으로 96 passed, 1 skipped 상태였습니다. 

python -m pytest
python -m ruff check

테스트 종류

종류 확인하는 것 예시
unit test 작은 함수 하나의 동작 FASTA parser, mutation parser
integration test 여러 모듈을 연결한 흐름 Nextclade result → antigenic scan
CLI smoke test 명령어가 최소 입력으로 실행되는지 python legacy/h3n2_ha_analysis.py --help
visual regression 이미지 생성이 깨지지 않았는지 tree PNG 파일 생성 여부와 크기 확인
end-to-end test 업로드부터 결과 표시까지 전체 흐름 웹서버 + 분석 runner + 결과 API

웹 개발 시 추가해야 할 테스트

  • 업로드 파일이 없을 때 적절한 오류를 반환하는지
  • 잘못된 FASTA가 들어왔을 때 분석을 시작하지 않는지
  • 분석 실패 시 status가 failed가 되는지
  • 완료 후 manifest를 정상 파싱하는지
  • 결과 파일 다운로드 API가 run 폴더 밖 파일을 읽지 못하는지
  • 프론트엔드가 running/completed/failed 상태를 올바르게 표시하는지

12. 배포와 운영

배포는 내 컴퓨터에서 돌아가는 프로그램을 다른 사람이 접속할 수 있는 환경에 올리는 것입니다. 이 프로젝트는 외부 CLI와 대용량 파일을 다루기 때문에 배포 방식 선택이 중요합니다.

선택지

방식 장점 단점 추천 단계
로컬 PC 서버 설치가 빠르고 비용이 적음 PC가 꺼지면 서비스 중단 초기 동아리 demo
연구실/학교 서버 데이터 관리와 내부 공유에 유리 서버 권한/설치 협의 필요 팀 사용
클라우드 VM 접근성과 확장성이 좋음 비용, 보안 설정 필요 외부 demo
Docker 환경 재현성이 좋음 처음 배우기 어렵고 IQ-TREE 포함 설정 필요 안정화 이후

Docker 개념

Docker는 서버 환경을 통째로 포장하는 방식입니다. Python, 패키지, IQ-TREE, TreeTime을 이미지 안에 넣으면 다른 서버에서도 비슷하게 실행할 수 있습니다. 

Docker image
  ├─ Linux base
  ├─ Python
  ├─ pip packages
  ├─ IQ-TREE binary
  ├─ TreeTime
  ├─ FastAPI server
  └─ Influmatics source code

운영에서 반드시 생각할 것

  • 동시에 몇 개의 분석을 허용할지
  • 한 run당 최대 업로드 용량
  • 결과 파일을 며칠 보관할지
  • 서버 디스크가 꽉 차면 어떻게 할지
  • 실패 로그를 어디까지 사용자에게 보여줄지
  • 내부용인지 외부 공개용인지
