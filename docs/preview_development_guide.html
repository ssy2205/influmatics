Influmatics Preview Development Guide

이 문서는 다른 작업자가 Influmatics UI나 기능을 수정한 뒤 자기 브랜치에 push하고, Firebase preview URL에서 바로 확인하는 방법을 설명합니다.

기준일: 2026-06-27 · repository: https://github.com/ssy2205/influmatics.git · Firebase project: influmatics-ca8ef

preview는 운영 live 앱을 바꾸지 않습니다. 브랜치/PR마다 임시 Firebase Hosting channel과 staging Cloud Run API를 사용해서 변경사항을 먼저 확인합니다.

1. 지금 만들어진 preview 구조

브랜치 push

JM 또는 codex/feature/frontend-ui 브랜치에 push하면 GitHub Actions Firebase Preview workflow가 실행됩니다.

push GitHub Actions

PR preview

main, JM, codex/feature/frontend-ui 대상으로 PR을 만들면 PR 번호 기반 preview channel이 배포됩니다.

pull request preview channel

Staging API

preview frontend는 운영 API가 아니라 staging API https://influmatics-api-staging-cxemvmm35q-du.a.run.app를 봅니다.

Cloud Run staging

Production 보호

운영 URL https://influmatics-ca8ef.web.app는 main 배포 workflow가 돌 때만 바뀝니다. 일반 브랜치 push는 live 앱을 바꾸지 않습니다.

production main
현재 검증된 개발 브랜치 preview URL: https://influmatics-ca8ef--branch-codex-feature-frontend-ui-zk3l5hza.web.app

2. 처음 작업하는 사람이 repo 받는 법

처음 clone한다면 아래처럼 시작합니다.

처음 clone 
git clone https://github.com/ssy2205/influmatics.git
cd influmatics
git fetch origin
git checkout codex/feature/frontend-ui
git pull origin codex/feature/frontend-ui
git status

이미 repo가 있다면 최신 상태로 맞춥니다.

기존 repo 갱신 
cd influmatics
git fetch origin
git checkout codex/feature/frontend-ui
git pull origin codex/feature/frontend-ui
git status --short --branch

3. 새 작업 브랜치 만들기

다른 사람의 변경과 섞이지 않게, 기능마다 새 브랜치를 만드는 것을 권장합니다. 브랜치 이름은 짧고 의미 있게 정합니다.

feature branch 생성 
git checkout codex/feature/frontend-ui
git pull origin codex/feature/frontend-ui
git checkout -b feature/my-ui-change
같은 브랜치에 여러 사람이 동시에 push하면 충돌이 늘어납니다. 가능하면 feature/... 브랜치에서 작업하고 PR을 만들어 preview를 확인하세요.

4. 로컬에서 UI 확인하기

프론트만 빠르게 볼 때는 Vite dev server를 사용합니다.

frontend dev server 
npm --prefix web/frontend ci
VITE_API_BASE=https://influmatics-api-staging-cxemvmm35q-du.a.run.app npm --prefix web/frontend run dev

브라우저에서 Vite가 알려주는 로컬 주소를 엽니다. 보통 http://localhost:5173입니다.

5. 수정하고 push하기

수정 후 build가 되는지 먼저 확인합니다.

검사와 push 
npm --prefix web/frontend run build
python3 -m py_compile web/server/gcs_store.py web/server/analysis_runner.py web/server/app.py tests/test_web_runner.py
git status --short
git add 수정한_파일들
git commit -m "Describe your change"
git push origin feature/my-ui-change
pytest가 설치된 환경이라면 python -m pytest 또는 python -m pytest tests/test_web_runner.py도 실행하세요.

6. preview URL 확인하기

push 후 GitHub Actions에서 workflow 실행을 확인합니다.

상황 어디서 확인하나 예상 결과
브랜치 push GitHub repository의 Actions 탭 Firebase Preview workflow가 실행됩니다.
PR 생성 PR 화면 또는 Actions 탭 PR 번호 기반 Firebase preview channel이 생성됩니다.
성공 여부 workflow run detail Deploy staging API, Deploy Firebase preview channel, Smoke test preview API가 성공해야 합니다.

터미널에서 확인하려면 GitHub CLI를 사용할 수 있습니다.

Actions 확인 
gh run list --repo ssy2205/influmatics --branch feature/my-ui-change --limit 5
gh run watch RUN_ID --repo ssy2205/influmatics --exit-status

7. preview에서 실제로 봐야 할 것

  1. 페이지가 열리고 Influmatics 제목과 탭들이 보이는지 확인합니다.
  2. Upload 탭에서 Target FASTA만 필수인지 확인합니다.
  3. Reference FASTA, Vaccine FASTA 입력칸은 보이지 않아야 합니다.
  4. Tree clade bar 옵션은 보여야 합니다.
  5. 작은 FASTA로 실행했을 때 Run Status가 completed가 되는지 확인합니다.
  6. Files 탭에서 CSV/PNG/HTML 결과 파일이 보이는지 확인합니다.
backend는 reference 업로드가 없어도 기본 H3N2 reference를 자동으로 넣습니다. 그래서 preview UI에서는 target만 업로드해도 분석이 진행되어야 합니다.

8. staging API 직접 smoke test

UI가 이상할 때는 API를 직접 확인하면 문제를 빨리 좁힐 수 있습니다.

API smoke test 
curl -s https://influmatics-api-staging-cxemvmm35q-du.a.run.app/health

curl -s -X POST https://influmatics-api-staging-cxemvmm35q-du.a.run.app/analyses \
  -F target=@data/references/A_Aichi_1968_H3N2_HA.fasta \
  -F tree_method=fast-upgma \
  > /tmp/influmatics_preview_run.json

python3 -c 'import json; print(json.load(open("/tmp/influmatics_preview_run.json"))["run_id"])'

run id를 얻은 뒤 아래 명령으로 상태와 결과를 확인합니다.

run 결과 확인 
RUN_ID=여기에_run_id_입력
curl -s "https://influmatics-api-staging-cxemvmm35q-du.a.run.app/analyses/${RUN_ID}/status"
curl -s "https://influmatics-api-staging-cxemvmm35q-du.a.run.app/analyses/${RUN_ID}/results" \
  > /tmp/influmatics_preview_results.json
python3 -c 'import json; d=json.load(open("/tmp/influmatics_preview_results.json")); print(d["status"], len(d["files"]))'

9. production 배포는 언제 되나

production workflow는 main 브랜치에 push되거나 GitHub에서 수동 실행할 때 동작합니다. 일반 feature branch push나 PR preview는 production live 앱을 바꾸지 않습니다.

URL 역할
https://influmatics-ca8ef.web.app 운영 live frontend
https://influmatics-api-cxemvmm35q-du.a.run.app 운영 API
https://influmatics-api-staging-cxemvmm35q-du.a.run.app preview/staging API

10. 자주 나는 문제

증상 확인할 것
Actions가 실행되지 않음 브랜치가 workflow trigger에 포함되어 있는지 확인합니다. 현재 push trigger는 JM, codex/feature/frontend-ui입니다. 다른 feature branch는 PR을 만들면 preview가 돕니다.
preview는 열리는데 API 호출 실패 preview bundle의 VITE_API_BASE가 staging API인지, staging API CORS가 preview URL을 허용하는지 확인합니다.
분석이 reference 파일 없음으로 실패 web/server/analysis_runner.py의 기본 reference 자동 복사 로직이 포함되어 있는지 확인합니다.
Firebase deploy 중 predeploy가 URL을 덮어씀 workflow의 Firebase deploy step에도 VITE_API_BASE env가 들어가 있어야 합니다.
GCS 결과가 안 보임 staging은 INFLUMATICS_RUNS_PREFIX=staging-runs, production은 runs prefix를 사용합니다.

11. 안전 범위

이 앱은 공개 과거 influenza A/H3N2 HA 서열의 후향 분석과 교육용 시각화 범위에서 개발합니다. 새 변이를 설계하거나 감염성, 전파력, 병원성, 면역회피, 내성을 높이는 변이를 추천/생성/순위화하지 않습니다. wet-lab protocol, synthesis, reverse genetics, virus rescue 내용도 넣지 않습니다.
