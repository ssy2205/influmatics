Influmatics Deployment and CI Handoff

이 문서는 다음 작업자가 Firebase/Cloud Run 배포와 GitHub Actions 자동 배포 구조를 이어서 만들 수 있도록 정리한 인수인계 문서입니다.

기준일: 2026-06-26 · 기준 branch: codex/feature/frontend-ui · repository: https://github.com/ssy2205/influmatics.git

현재 서비스는 공개 과거 influenza A/H3N2 HA 서열의 후향 분석과 교육용 시각화 범위로 유지해야 합니다. 새 변이 설계, 감염성/전파력/병원성/면역회피/내성 향상 추천, wet-lab protocol, synthesis, reverse genetics, virus rescue 기능은 넣지 않습니다.

2. 현재 repo 파일 구조에서 중요한 배포 파일

파일 역할
Dockerfile FastAPI backend를 Cloud Run에 올리는 이미지입니다. matplotlib font cache를 build time에 미리 만듭니다.
.gcloudignore, .dockerignore 배포/이미지 빌드에 불필요한 로컬 데이터, 결과물, node_modules를 제외합니다.
firebase.json, .firebaserc Firebase Hosting 설정입니다. build 후 web/frontend/dist를 배포합니다.
web/frontend/.env.production 프론트 production build의 VITE_API_BASE를 Cloud Run API로 지정합니다.
web/server/gcs_store.py run별 input/result/log/status를 GCS에 저장하고, 로컬에 없으면 GCS에서 복구합니다.
infra/gcs-lifecycle-24h.json GCS 결과 버킷에 적용한 24시간 삭제 lifecycle 정책입니다.
web/server/analysis_runner.py legacy CLI subprocess 실행, run directory 생성, GCS 동기화, manifest/file serving을 담당합니다.
web/server/app.py FastAPI endpoint와 CORS 설정입니다. Firebase Hosting origin을 허용합니다.

4. 수동 배포 명령

자동화가 완성되기 전에는 아래 명령으로 현재처럼 수동 배포할 수 있습니다. 네트워크, 인증, billing, IAM이 필요합니다.

Backend Cloud Run 배포

Cloud Run deploy 
gcloud config set project influmatics-ca8ef
gcloud run deploy influmatics-api \
  --source . \
  --region asia-northeast3 \
  --project influmatics-ca8ef \
  --allow-unauthenticated \
  --cpu 2 \
  --memory 4Gi \
  --timeout 3600 \
  --concurrency 1 \
  --max-instances 2 \
  --no-cpu-throttling \
  --set-env-vars RUN_RETENTION_HOURS=24,INFLUMATICS_RUNS_BUCKET=influmatics-ca8ef-runs,INFLUMATICS_RUNS_PREFIX=runs \
  --quiet

Frontend Firebase Hosting 배포

Firebase deploy 
npm --prefix web/frontend run build
NO_UPDATE_NOTIFIER=1 CI=true firebase deploy --project influmatics-ca8ef --only hosting

GCS bucket/lifecycle 재적용

GCS lifecycle 
gcloud storage buckets describe gs://influmatics-ca8ef-runs --format=json
gcloud storage buckets update gs://influmatics-ca8ef-runs --lifecycle-file=infra/gcs-lifecycle-24h.json
gcloud storage buckets update gs://influmatics-ca8ef-runs --clear-soft-delete

6. GitHub 수정이 바로 확인되는 권장 개발 구조

Pull Request preview

PR마다 Firebase Hosting preview channel을 만들고, GitHub Actions가 preview URL을 댓글로 남깁니다. UI 수정은 merge 전에도 브라우저에서 바로 확인할 수 있습니다.

firebase hosting:channel:deploy pull_request

Staging backend

influmatics-api-staging Cloud Run 서비스를 만들고 preview frontend는 이 API를 바라보게 합니다. production 데이터/트래픽과 분리됩니다.

Cloud Run staging VITE_API_BASE

Production deploy

main 또는 합의한 release branch에 merge될 때 Firebase Hosting production과 influmatics-api를 배포합니다.

push to main production

Safer authentication

GitHub Secrets에 장기 service account JSON key를 넣기보다 Workload Identity Federation을 권장합니다. 다음 작업자가 GCP IAM을 정리하면서 적용하세요.

Workload Identity Federation least privilege

권장 branch 흐름

  1. main: production 배포 기준 브랜치.
  2. codex/feature/frontend-ui 또는 feature branch: 개발/PR 기준.
  3. PR 생성 시 frontend preview + backend staging 배포.
  4. PR merge 시 production 배포.

7. GitHub Actions 작업 목록

현재 repo에는 아래 workflow들이 구성되어 있습니다.

Workflow Trigger 역할
.github/workflows/ci.yml pull_request, push frontend build, Python smoke/pytest, lint 가능하면 추가.
.github/workflows/firebase-preview.yml pull_request PR별 Firebase Hosting preview channel 배포. staging API URL을 VITE_API_BASE로 주입.
.github/workflows/deploy-production.yml push to main Cloud Run production + Firebase Hosting production 배포.

Preview workflow 뼈대

firebase-preview.yml draft 
name: Firebase Preview

on:
  pull_request:
    branches:
      - main
      - codex/feature/frontend-ui

permissions:
  contents: read
  checks: write
  pull-requests: write
  id-token: write

jobs:
  preview:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: web/frontend/package-lock.json

      - run: npm --prefix web/frontend ci
      - run: npm --prefix web/frontend run build
        env:
          VITE_API_BASE: https://STAGING_API_URL_HERE

      # TODO: configure Workload Identity Federation first.
      - uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
          service_account: ${{ secrets.GCP_SERVICE_ACCOUNT }}

      - run: npm install -g firebase-tools
      - run: firebase hosting:channel:deploy "pr-${{ github.event.pull_request.number }}" --project influmatics-ca8ef --expires 7d

Production workflow 뼈대

deploy-production.yml draft 
name: Deploy Production

on:
  push:
    branches:
      - main

permissions:
  contents: read
  id-token: write

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: google-github-actions/auth@v2
        with:
          workload_identity_provider: ${{ secrets.GCP_WORKLOAD_IDENTITY_PROVIDER }}
          service_account: ${{ secrets.GCP_SERVICE_ACCOUNT }}

      - uses: google-github-actions/setup-gcloud@v2

      - uses: actions/setup-node@v4
        with:
          node-version: 20
          cache: npm
          cache-dependency-path: web/frontend/package-lock.json

      - run: npm --prefix web/frontend ci
      - run: npm --prefix web/frontend run build
        env:
          VITE_API_BASE: https://influmatics-api-cxemvmm35q-du.a.run.app

      - run: |
          gcloud run deploy influmatics-api \
            --source . \
            --region asia-northeast3 \
            --project influmatics-ca8ef \
            --allow-unauthenticated \
            --cpu 2 \
            --memory 4Gi \
            --timeout 3600 \
            --concurrency 1 \
            --max-instances 2 \
            --no-cpu-throttling \
            --set-env-vars RUN_RETENTION_HOURS=24,INFLUMATICS_RUNS_BUCKET=influmatics-ca8ef-runs,INFLUMATICS_RUNS_PREFIX=runs \
            --quiet

      - run: npm install -g firebase-tools
      - run: firebase deploy --project influmatics-ca8ef --only hosting
Workload Identity Federation은 ssy2205/influmatics repository 조건으로 생성되어 있습니다. staging API는 https://influmatics-api-staging-cxemvmm35q-du.a.run.app이고, 개발 브랜치 preview channel은 https://influmatics-ca8ef--branch-codex-feature-frontend-ui-zk3l5hza.web.app로 검증했습니다.

9. 프론트/백엔드 기능 충돌 주의사항

  • Reference FASTA와 Vaccine FASTA 업로드 칸은 현재 프론트에서 숨겨져 있습니다.
  • 백엔드는 reference, vaccine 업로드를 optional로 받을 수 있습니다.
  • legacy/h3n2_ha_analysis.py는 reference/vaccine 파일이 없으면 스크립트 기본 동작을 사용합니다.
  • Tree clade bar UI는 유지되어야 합니다. tree_clade_bar option과 --tree-clade-bar 전달을 지우지 마세요.
  • 결과 파일명은 기존 분석 코드가 생성한 이름을 그대로 서빙합니다. 프론트에서 이름을 바꾸지 마세요.
  • Cloud Run은 background thread/subprocess를 계속 돌리기 위해 --no-cpu-throttling이 필요합니다.

11. 작업자에게 남기는 짧은 메모

이 프로젝트는 이미 “수동 배포가 되는 상태”까지 왔습니다. 다음 단계의 핵심은 새 기능을 만드는 것보다 배포 경로를 안정화하는 일입니다. GitHub에서 수정한 UI를 바로 보려면 PR preview를 먼저 만들고, 분석 서버는 staging/prod로 나누는 것이 가장 덜 헷갈립니다.

문제가 생기면 먼저 세 가지만 확인하세요: VITE_API_BASE, Cloud Run env, GCS bucket 권한. 이 셋이 맞으면 대부분의 배포 문제는 좁혀집니다.
