Influmatics Deployment and CI Handoff

이 문서는 프론트엔드/서버 담당자와 Codex가 현재 배포 구조를 바로 이어받을 수 있도록 정리한 인수인계 문서입니다. 기준 브랜치는 codex/feature/frontend-ui이며, 분석 엔진 기준 브랜치는 JM입니다.

작성 기준일: 2026-06-28 · repository: https://github.com/ssy2205/influmatics.git

서비스 범위는 공개 과거 influenza A/H3N2 HA 서열의 후향 분석과 교육용 시각화입니다. 새 변이 설계, 감염성/전파력/병원성/면역회피/항바이러스제 내성 향상 추천, wet-lab protocol, synthesis, reverse genetics, virus rescue 기능은 넣지 않습니다.

1. 현재 배포 구성 요약

항목 값 설명
Firebase project influmatics-ca8ef 프론트엔드 Hosting 프로젝트입니다.
Production frontend https://influmatics-ca8ef.web.app firebase.json에서 web/frontend/dist를 배포합니다.
Production API https://influmatics-api-cxemvmm35q-du.a.run.app Cloud Run service: influmatics-api, region: asia-northeast3.
Staging API influmatics-api-staging Preview frontend가 바라보는 Cloud Run staging service입니다.
Result bucket gs://influmatics-ca8ef-runs 분석 run의 input, result, log, status를 저장합니다. lifecycle은 1일 삭제 정책입니다.

2. 이미 반영된 핵심 요구사항

  • Reference FASTA, Vaccine FASTA 업로드 칸은 프론트엔드에서 숨겨져 있습니다.
  • 백엔드는 기존 호환성을 위해 reference, vaccine 업로드를 optional로 받을 수 있습니다.
  • reference가 없으면 서버가 내장 reference FASTA를 run input으로 복사합니다.
  • Tree clade bar 옵션은 UI, API schema, runner, legacy CLI 인자까지 연결되어 있습니다.
  • Cloud Run 배포에는 --no-cpu-throttling이 포함되어 subprocess 분석이 중간에 멈추지 않게 했습니다.
  • GCS 저장소가 설정되면 run 결과를 GCS에 동기화하고, 로컬에 없을 때 GCS에서 결과 파일을 다시 가져올 수 있습니다.
  • CI workflow는 .github/workflows/ci.yml로 정리했습니다.

3. 주요 파일 역할

파일 역할
Dockerfile FastAPI backend를 Cloud Run 이미지로 빌드합니다. .[web,bio], numpy, matplotlib, treetime을 설치합니다.
firebase.json, .firebaserc Firebase Hosting 설정입니다. frontend build 결과물 web/frontend/dist를 배포합니다.
web/frontend/.env.production production frontend가 바라볼 Cloud Run API URL을 정의합니다.
web/frontend/src/App.jsx 업로드 UI, 분석 옵션, 결과 탭을 담당합니다. reference/vaccine 입력칸은 이 파일에서 제거되었습니다.
web/server/app.py FastAPI endpoint, CORS, 파일 업로드, 분석 run API를 담당합니다.
web/server/analysis_runner.py run directory 생성, legacy CLI subprocess 실행, GCS 동기화, 결과 파일 목록 생성을 담당합니다.
web/server/gcs_store.py GCS upload/download/list 로직을 담당합니다.
infra/gcs-lifecycle-24h.json GCS 결과 파일을 1일 후 삭제하는 lifecycle 정책입니다.

4. 다음 작업자가 코드를 받는 방법

처음 받는 경우

git clone https://github.com/ssy2205/influmatics.git
cd influmatics
git checkout codex/feature/frontend-ui
git pull origin codex/feature/frontend-ui

이미 폴더가 있는 경우

cd influmatics
git fetch origin
git checkout codex/feature/frontend-ui
git pull origin codex/feature/frontend-ui
git status --short --branch
작업 전에는 반드시 git status --short --branch로 로컬 변경사항이 있는지 확인하세요. 사용자가 만든 변경사항을 임의로 되돌리지 않습니다.

5. 로컬 실행 방법

Python backend

python -m venv .venv
.venv\Scripts\activate
python -m pip install -e ".[dev,web,bio]" numpy matplotlib treetime
python -m uvicorn web.server.app:app --reload --host 127.0.0.1 --port 8000

React frontend

cd web/frontend
npm ci
npm run dev

개발 모드에서 frontend 기본 API는 http://localhost:8000입니다. production build는 web/frontend/.env.production의 VITE_API_BASE를 사용합니다.

6. GitHub Actions 구조

Workflow Trigger 역할
.github/workflows/ci.yml pull_request, push to main Python pytest/compile과 frontend build를 실행합니다.
.github/workflows/firebase-preview.yml pull_request, push to JM or codex/feature/frontend-ui, manual staging API를 배포하고 Firebase preview channel을 생성합니다.
.github/workflows/deploy-production.yml push to main, manual production Cloud Run API와 Firebase Hosting을 배포합니다.
production 사이트가 예전 화면을 보여도 source branch가 틀린 것은 아닐 수 있습니다. production workflow는 main push 또는 수동 실행 기준이므로, feature branch의 변경사항은 preview channel에서 먼저 확인됩니다.

7. 수동 배포 명령

Backend Cloud Run

gcloud config set project influmatics-ca8ef
gcloud run deploy influmatics-api \
  --source . \
  --region asia-northeast3 \
  --project influmatics-ca8ef \
  --allow-unauthenticated \
  --cpu 2 \
  --memory 4Gi \
  --timeout 3600 \
  --concurrency 1 \
  --max-instances 2 \
  --no-cpu-throttling \
  --set-env-vars RUN_RETENTION_HOURS=24,INFLUMATICS_RUNS_BUCKET=influmatics-ca8ef-runs,INFLUMATICS_RUNS_PREFIX=runs \
  --quiet

Frontend Firebase Hosting

npm --prefix web/frontend run build
NO_UPDATE_NOTIFIER=1 CI=true firebase deploy --project influmatics-ca8ef --only hosting

9. 프론트엔드/백엔드 충돌 주의사항

  • 프론트엔드에 reference/vaccine 입력칸을 다시 노출하지 않습니다.
  • 백엔드 optional upload 필드는 유지합니다. 기존 API 호환성과 테스트 편의성을 위해 필요합니다.
  • 결과 파일명은 가능한 한 바꾸지 않습니다. 프론트엔드는 파일명으로 결과 이미지를 찾습니다.
  • tree_clade_bar 옵션 전달 경로를 끊지 않습니다.
  • Cloud Run에서 subprocess를 돌리므로 timeout, memory, CPU throttling 설정을 함부로 낮추지 않습니다.
  • GISAID 등 재배포 제한이 있는 서열을 repo에 커밋하지 않습니다.

10. 안전 기능 경계

이 서비스는 과거 공개 데이터 기반 분석 대시보드입니다. 출력은 해석, 비교, 시각화 중심이어야 하며 새로운 변이를 만들거나 선택하도록 유도하면 안 됩니다.

  • 허용: clade/subclade annotation, tree visualization, antigenic site difference visualization, QC/outlier report.
  • 허용: 과거 관찰 서열의 codon variability, retrospective trend, educational summary.
  • 금지: 감염성, 전파력, 병원성, 면역회피, 항바이러스제 내성 향상을 위한 변이 추천 또는 순위화.
  • 금지: wet-lab protocol, synthesis, reverse genetics, virus rescue, 배양 조건 제공.
  • 주의: protein language model은 표현학습/분류/후향적 추세 분석에만 사용하고, 미래 변이 설계 도구로 만들지 않습니다.
