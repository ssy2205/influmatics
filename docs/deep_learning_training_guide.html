딥러닝 학습은 데이터부터, 서버는 나중에 결정합니다

인플루엔자 HA1 단백질 서열로 항원성 좌표나 novelty score를 예측하려면 데이터와 라벨이 먼저 필요합니다. 서버는 처음부터 빌리는 것이 아니라, baseline 실험 후 PLM 임베딩이나 파인튜닝 단계에서 필요한 만큼 선택하는 것이 안전합니다.

목차

1. 바로 답하기 2. 어떤 데이터를 모을까 3. 서버가 필요한 시점 4. 실제 학습 단계 5. 현재 코드로 돌리는 법 6. 라벨 전략 7. 평가와 검증 8. 추천 진행 순서 9. 흔한 실수

1. 바로 답하기

딥러닝을 진행하려면 결국 데이터는 모아야 합니다. 하지만 서버를 바로 빌릴 필요는 없습니다. 현재 코드로는 로컬 CPU에서도 데이터 검증, feature 생성, dataset build, ridge baseline 학습까지 할 수 있습니다.

서버가 꼭 필요한가? 처음에는 아닙니다. toy 데이터와 baseline은 로컬에서 충분합니다. 수천 개 이상의 서열에 PLM 임베딩을 만들거나 모델을 fine-tuning할 때 GPU 서버가 필요합니다.
데이터가 꼭 필요한가? 네. supervised 모델은 서열뿐 아니라 정답 라벨이 필요합니다. 예: antigenic map 좌표, HI assay 기반 거리, vaccine mismatch label.
먼저 할 일은? H3N2 HA1로 범위를 고정하고, 공개 FASTA와 metadata, 라벨 TSV를 정리한 뒤 baseline 성능을 확인합니다.

2. 어떤 데이터를 모을까

모델 학습에는 입력 X와 정답 y가 필요합니다. 여기서 X는 단백질 서열과 metadata이고, y는 항원성 좌표나 항원성 변화 정도 같은 라벨입니다.

필수 데이터

종류 예시 왜 필요한가
Protein FASTA H3N2 HA1 amino-acid sequence 모델 입력입니다. 먼저 HA1로 범위를 좁히는 것이 좋습니다.
Metadata TSV seq_id, year, subtype, gene, country, clade 시간 분할, clade 분석, 데이터 누수 확인에 필요합니다.
Label TSV antigenic_x, antigenic_y 또는 novelty class 정답입니다. 라벨이 없으면 supervised 학습을 할 수 없습니다.
AA mutation TSV N145K, S193F, coordinate_space=aa 항원 부위 변이 수 같은 해석 가능한 feature를 만들 때 사용합니다.
데이터 권한: GISAID 데이터는 저장소에 넣지 마세요. 공개 데이터는 NCBI/IRD/논문 supplementary data처럼 재사용 가능한 출처부터 시작하는 것이 좋습니다.

3. 서버가 필요한 시점

서버는 모델 단계에 따라 필요성이 다릅니다. 비용을 쓰기 전에 로컬에서 데이터가 제대로 연결되는지 확인하는 편이 훨씬 효율적입니다.

단계 서버/GPU 필요성 추천 환경
데이터 정리, QC, TSV 검증 필요 없음 로컬 CPU
AA composition, mutation count, ridge baseline 필요 없음 로컬 CPU
ESM-2/ProtBERT frozen embedding 추출 서열 수가 많으면 GPU 권장 Colab, 연구실 GPU, 클라우드 GPU
PLM fine-tuning GPU 필요 12GB 이상 GPU부터 검토, 큰 모델은 더 많은 VRAM 필요
학습된 모델 추론/리포트 대개 필요 없음 로컬 CPU 또는 작은 서버
추천 판단: 처음 1-2주는 서버를 빌리지 말고 로컬에서 baseline까지 완성하세요. 라벨 row가 충분하고 baseline이 의미 있게 움직이면 그때 GPU를 빌려 PLM embedding을 만듭니다.

4. 실제 학습 단계

학습은 한 번에 “큰 모델”로 가지 말고, 아래 순서로 쌓아가는 것이 좋습니다.

Phase 1 데이터 스키마를 맞추고 toy 데이터로 end-to-end를 확인합니다.
Phase 2 실제 FASTA/metadata/label을 넣어 ridge baseline을 학습합니다.
Phase 3 ESM-2 또는 ProtBERT embedding을 추출하고 작은 regression head를 학습합니다.
Phase 4 충분한 라벨이 있을 때 fine-tuning과 single mutation scan을 진행합니다.

6. 라벨 전략

좋은 모델은 좋은 라벨에서 나옵니다. FASTA가 많아도 라벨이 없으면 항원성 예측 모델은 학습하기 어렵습니다.

라벨 장점 주의점
Antigenic map coordinate 회귀 모델에 바로 사용 가능 공개 좌표 수가 제한적일 수 있음
HI assay table pairwise antigenic distance로 변환 가능 실험 조건과 strain naming 정리가 필요
Vaccine match/mismatch 분류 문제로 단순화 가능 정량적 항원성보다 거친 라벨
Proxy label 초기 파이프라인 점검에 좋음 논문 결과로 주장하기에는 약함

7. 평가와 검증

인플루엔자 서열은 서로 매우 비슷한 경우가 많아서 random split만 쓰면 성능이 과대평가될 수 있습니다. 시간 기준 split과 생물학적 sanity check를 같이 사용하세요.

Temporal split
예: 2021년까지 train, 2022년 valid, 2023년 이후 test.
Metric
좌표 회귀는 MAE/RMSE, pairwise distance는 correlation을 봅니다.
Leakage check
거의 같은 strain이 train/test에 동시에 들어가지 않았는지 확인합니다.
Biology check
H3 145, 155, 156, 158, 159, 189, 193 등 핵심 위치가 의미 있게 반영되는지 봅니다.

8. 추천 진행 순서

  1. H3N2 HA1을 1차 목표로 확정합니다.
  2. 공개 FASTA와 metadata를 모으고 seq_id를 통일합니다.
  3. antigenic coordinate, HI table, vaccine mismatch 중 하나를 라벨로 정리합니다.
  4. 현재 코드로 manifest, validation, dataset build, ridge baseline을 실행합니다.
  5. baseline metric이 말이 되는지 확인합니다.
  6. 라벨 row가 충분하면 GPU에서 ESM-2/ProtBERT embedding을 추출합니다.
  7. embedding + 작은 regression head 모델을 baseline과 비교합니다.
  8. 충분한 데이터와 GPU가 확보되면 fine-tuning을 검토합니다.
실무 추천: 서버를 빌리기 전 목표는 “실제 label dataset으로 ridge baseline까지 돌아간다”입니다. 이 단계가 끝나야 GPU 비용을 써도 무엇을 비교할지 명확해집니다.

9. 흔한 실수

실수 왜 문제인가 피하는 법
FASTA만 모으고 라벨을 나중에 찾음 학습 목표가 불명확해져 모델을 만들 수 없음 서열 수집과 동시에 label source를 정합니다.
random split 성능만 보고 결론 냄 유사 서열 때문에 미래 예측 성능이 부풀 수 있음 temporal split을 기본으로 사용합니다.
GISAID 데이터를 저장소에 넣음 라이선스/공유 정책 위반 위험 제한 데이터는 저장소 밖 또는 ignored private path에 둡니다.
처음부터 큰 모델 fine-tuning 비용이 크고 실패 원인을 찾기 어려움 baseline -> frozen embedding -> fine-tuning 순서로 갑니다.
